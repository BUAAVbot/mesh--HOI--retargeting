# 双五指可见性与腕部碰撞修正

本阶段在第三阶段冻结的 121 帧轨迹上修正深度分支和腕壳碰撞，计算仍在 `yz-ai-4090-01.bce:/data/KinoGen`，本地只做文件校验和视频预览。相机、箱体、地板、G1/ROHand 模型和原视频均保持冻结，所有优化与条件候选分别留有来源和失败标记。

## 实际修复与保留的不确定性

第三阶段第 54 帧原图有 1588 个可见灰手像素，完整模型却被箱体遮住，实际可见像素为 0。沿源图射线检查发现，手模型比箱体前表面深约 166 mm。原简化链接轮廓代理忽略了完整场景遮挡，零穿透并不能保证重建与视频一致。

第四阶段使用固定的 RGB/SAM 灰手域、实际肩肘腕观测、原机器人网格和箱体射线深度关系优化。投影模型不参与挑选源像素；箱面条件点仅作初始化，不作为测量得到的三维点。所有关节仍受原位置界和明确正速度限制约束，缺测点保持未知。ROHand 速度/力矩的原零占位字段不被当成真实硬件参数。

第 54 帧恢复了真实前景手部。独立原始网格检查：最小手箱距离约 +0.200 mm、真实腕误差 3.301 px、原加权训练误差 1.704 px、原 12 点代理留出 4.482 px，均在原门槛内。完整原始三角面 GPU 渲染得到 832 个域内可见手像素，IoU 约 0.508。该完整可见网格指标与代理误差分别记录，不混用定义。

第 32、33 帧同样从远侧深度分支移到真实可见前面分支，原始手网格检查无穿透、身体图像与速度门槛通过。相应原始射线可见灰手像素由 0/1 增至 927/900。其余六个已知缺失帧（53、56、57、59、61、62）各执行一次有预算的实际图像优化，失败候选及精确回退完整保留。

严格零穿透目标与原有 **5 mm 必要采样检查** 分开。第 56、57 帧的可见前面候选分别仍有约 0.235/0.135 mm 手部采样穿透，以及约 2.639/4.305 mm 非手部腕壳采样穿透；这些候选保持零目标失败和条件标记，不改判严格通过。其原图像、手腕和位置/速度门槛仍逐项复核。最终采用帧和原始数值以总报告为准。

第 59 帧最后一次局部手臂修复把条件前景初值的 7.121 mm 腕壳穿透降至 0，真实腕误差 3.628 px 未超过原 3.675 px 预算，原图像门槛和相邻帧正速度限制通过。其右手离箱约 14.434 mm，因此不宣称真实接触或可靠抓取；条件初始化产生的控制状态仍保持三维未知。

检查扩展到腕壳后，还发现第三阶段第 70 帧有约 25.292 mm 腕壳穿箱，原来的 52 个手部 visual 检查没有覆盖这一部分。局部手臂修复将该帧腕壳与手部采样穿透降至 0；右腕与手部没有可靠观测，控制量和未知标记保留，不虚构手部拟合通过。全片另有原先就存在的 5 mm 以下非手部 visual 接触，不能称为整机器人严格零碰撞。

这些结果仍是已知模型与条件相机下的三维候选。箱体仍仅 56/121 帧严格有效；生成视频的两视角未必物理一致，ROHand 外形和虚拟安装座也未验证与生成的人形五指一致。未进行实机、力矩、动力学、连续三角面碰撞、完整自碰撞或物理策略跟踪。

最终导出包含全部 121 帧、24 FPS。相同原始手网格和完整场景深度下，右手 58 个可用源图域的缺失轮廓从 9 帧降至 0，轮廓 IoU 中位数从 0.3884 升至 0.5093；左手 79 个可用域仍为 0 个缺失。其余源图缺测域保持未知，轮廓存在也不代表三维姿态已被观测。全片手部最大采样穿透为 0.235 mm，非手部最大 4.898 mm，均未超过原 5 mm 必要界限。最终身体 `candidate_valid` 仍为 116/121，五个条件帧没有被改判严格通过。

最终独立汇总的必要几何检查与所审计图像门槛均通过；两段 MP4 均独立解码 121 帧且时间戳匹配 24 FPS，四个 GLB、动画变换、原始 XML/FK、厂家耦合及文件 SHA 均通过检查。按大于 1 微米的独立零目标诊断，手部失败帧为 56、57，非手部为 32、36、54、55、56、57、58；它们未被 5 mm 必要检查通过覆盖或删除。双手全部 6050 个关节条目仍保持三维不确定，`overall_reconstruction_success=false`，并非完整物理重建成功。

“所审计图像门槛通过”仅覆盖最终报告明确列出的检查，不等于每帧双手都通过。第 26 帧身体、基座和手指保持第三阶段原值，其右手代理留出约 4.606 px，仍高于原 4.5 px 门槛，严格图像标记保留 false；该帧左手缺测且离箱约 72 mm。全片手部二维通过帧数仍仅左 20、右 32，缺测与失败帧没有补成通过。

服务器可只读复核保存的最终文件，并写入新的报告，不覆盖本阶段冻结报告：

```bash
cd /data/KinoGen
source scripts/activate-server.sh vision
CUDA_VISIBLE_DEVICES= python scripts/verify_user_reconstruction_v3.py \
  --body-file outputs/user_reconstruction_v4/body_trajectory.npz \
  --hand-file outputs/user_reconstruction_v4/hand_trajectory.npz \
  --full-file outputs/user_reconstruction_v4/full_trajectory.npz \
  --scene-report reports/user-full-scene-v4.json \
  --provenance-report reports/user-v4-canonical-provenance.json \
  --output "reports/user-v4-core-recheck-$(date -u +%Y%m%dT%H%M%SZ).json"
```

此入口名称沿用已冻结的独立验证器，它检查必要采样、参数、来源、动画及视频，不能替代总报告中完整可见性、各阶段原图像门槛和零目标失败清单。`strict_metric_reconstruction_valid=false` 与 `physical_hardware_validated=false` 始终保留。
